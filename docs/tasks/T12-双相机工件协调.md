# T12：双相机工件协调

前置T11已由VAL-013全量验收；A05采用既有组合ResourceBudget，A06见ADR-012。
本任务限定Demo、单工位/双相机/一个在途工件/一个未消费终态事件。
Production明确拒绝；不存在模拟成功自动切生产的路径。

应用层Station持有两个Camera Session、两个Algorithm Session及纯领域Inspection。
触发前一次预留两相机、两算法、结果容量；主事件线程是唯一提交者，无外部并发接纳。
部分派发失败形成Unknown终态并取消其他在途；OS资源停止前不能释放票据。
使用单调工件期限，采集和算法都只拿剩余预算，不在每阶段重新获得完整时限。
结果通过Inspection校验完整任务关联并统一判定；统一ResultCounter计数。

暂停只撤销新接纳，已接纳工件仍正常完成；故障终态转Faulted。
过期、缺帧、崩溃、重复/乱序图像不能当OK。恢复目前重建Station/新run，
不自动重放旧工件。最多4096件后需新会话，不能让去重账本无限增长。

运行时内核不加入产品规则；Qt只在application/qt适配层使用。
当前序列工作站使用现有Session的接纳与期限，不再添加第二套任务调度队列。
T14将输出通道容量及交付状态接入，T16实现配方变更。

验收：10项真实四worker集成+全部既有测试，覆盖正常、NG、暂停、超时、
缺帧、算法崩溃、取消、重复帧、乱序帧、未消费结果背压；Production拒绝、
重复触发、质量与结果Schema、计数、退出零租约/零票据在每场景检查。
