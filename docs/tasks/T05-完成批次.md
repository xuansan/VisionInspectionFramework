# T05 完成批次

日期：2026-09-19。依据用户批准继续 T05、测试通过后交付的要求；继承 T05 任务卡与主计划8.1。

## 实施与验收顺序

1. 固定 protocol 1.0 的公共头及15种消息的最小严格 payload；JSON 重复键、UTF-8、深度、字节大小、枚举和跨字段身份不一致均拒绝。
2. 纯 C++ Channel 组合 Decoder/Session，普通/控制独立发送容量，接收按消费回调同步处理、不积累额外无界事件；支持有限待请求和超时。
3. Qt LocalConnection 拥有一个 socket，只在同一个事件线程调用；有限读取/写入批次，bytesToWrite 上限；连接、握手、半包与写停滞超时；不使用阻塞 wait API。
4. 双向 Hello：客户端先发，服务端验凭据后回复；回复仍按同一会话身份验证。Hello 不表示生产 Ready。
5. Configure 等待 Ready；SubmitTask 等待 TaskFinished（TaskAccepted/TaskProgress 不结束请求）。请求 ID 本连接不复用；逾期结果不接纳，诊断可追踪。其他消息为通知，业务交付确认在后续任务实现。
6. 拒绝队列满不算发送成功；断线待请求标 Unknown，不自动重发。控制消息优先但不能穿插进已发送一半的帧。
7. 核心单元与真实子进程测试通过后，更新主计划、协议说明、进度与验收。

## 范围边界

定义本阶段可校验的控制载荷，不提前实现 SDK、图像租约、算法、生产联锁。Frame/结果引用及配置资产只验证协议含义，后续领域适配仍须校验存在性和权限。此连接不是对恶意同账户进程的安全沙箱。

不得通过把配置/任务对象任意透传 JSON 来假装完成载荷校验。扩展字段/消息须明确升级版本，不默认接受未知字段。
