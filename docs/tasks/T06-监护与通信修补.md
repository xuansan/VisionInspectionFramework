# T06：通信修补与 Windows 监护

日期：2026-09-19。用户已批准先修补再继续多个阶段，沿用主计划的小内核和 Windows 优先范围。

状态：Windows基础范围已完成，见[VAL-009](../acceptance/VAL-20260919-009-监护与调度验收.md)和[ADR-007](../decisions/ADR-007-监护健康与调度边界.md)。配置前启动期孤儿与公共插件宿主继续在T09处理；真实设备控制权仍待T13/T23。

## 实施顺序和退出条件

1. IPC：终态在交给调用方前仍占有 pending；排队期间不再超时，关闭则逐请求 Unknown。回调异常分别隔离。补队列满、断线、重复回复和异常回调回归。
2. runtime：纯 C++ 监护状态机、单调时钟、epoch、阶段期限、心跳与工作进展分别计时、有限退避/重启、等待 OS 退出后重启。健康租约只接受当前身份和严格递增序号，过期后不能原地复活。
3. Windows 适配：固定工位的全局命名互斥量；QProcess / LocalConnection 宿主启动、配置、监护与有限停止。实际子进程验证崩溃、卡死、旧 epoch、停止及隔离。
4. T07：仅在上述通过后推进有界调度、取消及资源保留规则；按实际完成范围记录，不把单元状态机等同图像生产闭环。

## 约束

- 正常停止先发 Stop，超过宽限终止自己持有的进程；退出确认前不能启动替代实例。
- 重启次数为本次显式启动会话的累计预算，短暂 Ready 不清零；人工再次启动才重置。
- 会话请求预算耗尽须在应用排空后轮换，不能在有任务时直接换连接。
- 主控健康由协调事件循环提供，宿主在自己的时钟上计 TTL；旧序号不能延长租约。
- 同工位第二主控失败关闭；主控重启不得自动进入生产。Windows 锁不是 PLC 的设备控制权，现场接管与 PLC fencing 仍在 T13/T23 验收。
- 不加入 Qt 商业模块，不改变质量判断，不实施 Linux。

## 自审

领域不依赖 runtime；runtime 不依赖 Qt。异常回调不能保证业务已处理，所以回调失败应关闭并让应用按连接失效结算。OS 退出、任务终态和资源可回收为三个不同事实。
