# T11～T16 顺序实施与验收

日期：2026-09-19。依据已批准主计划；Windows、Demo，生产模式保持禁用。

每个父任务独立完成后执行 `node tools/build.cjs windows-all`，包含全部既有测试、
新增测试及 Schema/CLI 校验。失败先修复并重新全量验证，保留原始失败日志。
不以本批次计划代替完成证据。

1. T11：确定性亮度区间算法、真实 Algorithm DLL、InspectTask、只读共享图像、
   算法进程租约移交；正常/NG/取消/超时/崩溃/坏描述/并行隔离和退出清算。
2. T12：双相机检测协调、工件级一次接纳、一次终态、暂停/排空/异常状态；
   A06恢复矩阵先落文档；运行端禁用Production。
3. T13：独立模拟Communication插件及设备宿主；到位沿、设备会话、就绪租约、
   结果关联ACK与过期；不确定物理动作不重放。
4. T14：独立ResultOutput宿主、有界分发及每通道状态、Demo outbox；
   A04先定义事务/幂等/重启边界；阻塞通道不影响另一通道。
5. T15：真实链路CLI和最小Qt状态页，单工位双相机配方；显式Demo，
   无SDK/GPU/RustFS依赖；注入算法/输出故障，清晰显示Unknown及交付状态。
6. T16：配方严格验证、不可变快照、原子保存、闲置切换与回退；
   活跃工件不混用版本；写入失败和中断测试。

选择独立业务适配层组合现有ProcessHost/BufferBroker，而不是扩充runtime的业务职责。
共享图像采用已有租约的原子移交，不复制整图穿过IPC，也不把JSON塞入input_ref。
T11固定亮度算法是基础链路验证；ONNX仍属T17～T19。
