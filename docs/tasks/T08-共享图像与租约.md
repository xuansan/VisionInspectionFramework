# T08：共享图像内存、租约与回收

日期：2026-09-19。依据主计划§8和ADR-002/005/007；用户已批准连续推进T08/T09。

状态：T08a/b/c及父级Windows基础验收通过，见[VAL-010](../acceptance/VAL-20260919-010-共享图像与插件宿主验收.md)和[ADR-008](../decisions/ADR-008-共享图像与插件宿主边界.md)。约3秒传输试验不等于长期性能验收；真实采集工作流待T10。

## 已批准方向的实施细化

1. T08a：contracts中定义Mono8/RGB8/BGR8布局和完整租约身份；runtime的BufferBroker只管理槽位和租约，不接触像素。Windows适配采用页文件映射、固定宽度头和每槽命名mutex。消费者以只读映射读取；不使用跨进程STL或自制无锁队列。
2. 写者持有槽位mutex完成拷贝和头部发布；消费者取得同一mutex后核对布局/代次/帧号再读取。控制端只做零等待操作；消费者等待有毫秒上限。写回调收到Busy立即返回，不在SDK回调无限等待。WAIT_ABANDONED视为内容不可信，停止使用并隔离该槽位，不能当成功继续读。
3. T08b：broker单事件线程持有完整run/pool/worker/epoch/lease/generation账本；写许可和读许可数量有界，发布前一次性登记全部消费者。每个消费者只有匹配自己身份的释放权，重复释放不扣减，旧代次不能释放新数据。
4. T08c：超时只标Retiring，不提前复用。已确认停止的释放或可信OS退出可撤销对应租约；writer未发布就退出，该帧作废。新主控用新run/pool；任何旧池映射仍在也不复用其名字。
5. 预览通过有限的最新图像副本，不向UI转移正式租约。框架API不自动把任意插件视为可信消费者；这里提供进程隔离和协议正确性，不宣称同账户恶意代码沙箱。

## 验收顺序

- 纯模型：布局乘加溢出、stride/format/length、池与身份校验、全满、读租约原子登记、旧epoch/重复释放、超时未停止、进程退出范围。
- Windows真实子进程：写/读校验，多消费者、只读映射、部分写者被结束、mutex遗弃、慢读者超时隔离、旧映射/旧描述拒绝、其他池不受影响。
- ADR-002两档图像尺寸及两池容量实验：记录实际帧数、耗时、吞吐、延迟分布、进程CPU/RSS、槽位高水位。结果是内存传输实验，不是推理性能或产线节拍承诺。
- 三preset回归后记录父级验收，再进入T09。缺失证据不得标记父任务完成。

## 同步依据

Windows官方资料：Microsoft Learn `Sharing Files and Memory`、`MapViewOfFile`、`Mutex Objects`。映射本身不提供发布同步，消费者映射选择FILE_MAP_READ；mutex遗弃意味着受保护内容不可信。

## 自审

控制/数据分离；不会把超时等同停止；池大小和租约历史不会无限增长。异常映射不自动删除别的进程资源。共享像素的边界仅在已验证的Windows x64构建成立，Linux后移。
