# 消息队列插件实施计划

2026-10-10，用户已批准实施。Windows 优先，Production 继续禁用。

范围：迁移 MQTT 到 plugins/message-queue/mqtt，增加 kafka、rabbitmq、
nats-jetstream。每项独立 ResultOutput、独立 worker-host、可选构建，
不把消息库引入 runtime 或 UI，不把不同协议实现堆进一个插件。

阶段：
1. 迁移 MQTT，保持 ID/参数/协议，修订构建和路径并跑全量回归。
2. Kafka：成熟 librdkafka 客户端、有界生产与回执读取。
3. RabbitMQ：rabbitmq-c、mandatory 路由、发布确认与业务回执。
4. NATS JetStream：nats.c、持久发布确认与业务回执。
5. 软件对端故障测试、实际消息服务集成测试、全量回归及文档。

共同契约：发送原 envelope，保留 event_id/output_instance_id/attempt；
只传结果与图像引用。消息系统确认不等于业务成功，只有关联的业务
BusinessAcked 才向既有分发器返回成功。超时/断线不得伪造确认。
接收业务程序必须按 event_id 去重并针对当前 attempt 回执。
自动重放要求 NonPhysicalIdempotent 声明，不重放执行器动作。

所有等待、队列、报文和重试有界。宿主仍是停止和崩溃处置边界。
协议库自身分配限制和插件输入限制分别说明，不声称抵御恶意 broker。
每项记录依赖固定版本、源码来源、许可证与实际测试范围。

本机已安装 Docker CLI，但初检 daemon 不可用；不得把 CLI 存在
等同于服务已可用。不修改系统特性，优先研究已有环境与独立服务。
真实服务不可用必须保留未验收状态，不以模拟通过替代。
