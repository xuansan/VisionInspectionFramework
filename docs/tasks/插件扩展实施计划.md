# 插件扩展实施计划

日期：2026-10-09。用户已批准分批设计及开发。

## 范围与顺序

1. 第一批：Webhook、MQTT、RustFS/S3 对象存储调用闭环。
2. 第二批：串口、Modbus RTU、OPC UA 客户端。
3. 第三批：测量、匹配、定位、条码。
4. 其他品牌相机、IO、光源需明确厂商 SDK 或设备协议后实施，不生成占位插件。

独立模块分别实现和验证；任何一项失败不能靠缩减测试完成验收。
不修改既有父任务完成数，不开启 Production。

## 共同约束

- 插件在独立 worker-host 进程运行，协议代码不进入 runtime 内核。
- 有界接收、响应、超时、重试与退出；一个输出失败不阻塞健康输出。
- 原样保持 event_id、output_instance_id、attempt，不生成假回执。
- 网络接收、broker ACK、业务处理确认必须区分。
- 输出重试沿用 Dispatcher / 持久交付管理，不在插件内叠加无限重试。
- 测试只连接本机测试服务，不向现场 PLC 发动作。
- 外部库需要固定来源与许可记录；不自行实现完整 MQTT 或 OPC UA 协议栈。

## Webhook 实施契约

新增 ResultOutput 插件 vision.webhook-output。复用现有 AsyncOutput 与 worker-host。
使用现有 libcurl，不增加 Qt 依赖。

配置：url、token_env、timeout_ms。只允许 HTTPS，另允许显式 127.0.0.1
HTTP 用于本地测试。拒绝 URL 用户信息、fragment、控制字符和查询参数。
token_env 指向环境变量，令牌不写进配置文件。
连接与整体请求有界，不跟随重定向、不使用环境代理、不关闭 TLS 验证。

每次投递发送原始 envelope JSON：
Authorization: Bearer <token>，Idempotency-Key: <event_id>。
接收端应以 event_id 去重并验证同一事件的内容一致，重复请求返回相同业务回执。
回执上限 4096 字节；必须是无重复键的 JSON，包含且仅包含
event_id 和 state，前者匹配请求，后者为 BusinessAcked。
仅 HTTP 2xx 且回执符合契约才报告 BusinessAcked。
普通 200、202 空回执、错事件、重定向、HTTP 错误、断线、超时都不报告业务成功。
这表示远端按照约定声明已处理，不构成对远端实现正确性的独立证明。
失败通过现有 Failed 报告交付管理，保留重试造成重复处理的可能性。

## MQTT 契约

复用 Eclipse Paho C 1.3.15 异步客户端，不自行实现协议栈。
当前配置仅接受 tcp://127.0.0.1:port，主题及实例身份有长度约束。
清洁会话、QoS1、不保留结果、不离线缓存、不自动无限重连。
一次投递包含连接、订阅、发布和业务回执，总期限 100..800ms。
必须同时收到 PUBACK 和关联 event_id/output_instance_id/attempt 的
非 retained BusinessAcked JSON 才确认成功。仅 broker 接收不够。
详见 plugins/message-queue/mqtt/README.md；远端 TLS/认证与正式 broker 压测另行验收。

## 对象存储契约

ObjectStorage 与 ResultOutput 使用同一有界投递任务，但由宿主按 Kind
调用不同 SDK 接口，不改变 ABI 或把 S3 放进 runtime。
S3 插件只接受已经提交并且内容相同的结果，上传同次检测的 1..4 张原图。
持久绑定目的地，PUT 后 GET 哈希一致才 Available，上传尝试每图最多三次。
与存储工具共享上传锁。失败、锁冲突、超时不能变成存储成功。
对象为原始像素；不是自动图像编码、掩码持久化或远端管理平台。
详见 plugins/s3-storage/README.md。

## 持久重放边界

网络 Webhook/MQTT 必须显式声明 replay_policy=NonPhysicalIdempotent
才进入持久 agent 白名单。使用方必须核实接收服务非物理且实现去重。
这不是自动证明，更不得用来为 PLC/执行器动作授权重放。
S3 回执代表存储验证，不代表远端 MES 已消费。各输出状态仍分别统计。

第一批验收不得代替第二/三批；新增插件不自动关闭 T22～T27 父任务，
Production 仍禁用，也不宣称框架已经具备完整设备或传统视觉算法库。
