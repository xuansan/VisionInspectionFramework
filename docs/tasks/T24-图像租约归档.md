# T24 图像租约归档与追溯联接

2026-09-19，延续已批准的T24/T27存储闭环计划。

本批在持久模拟中接入双相机原始图像归档。流程为采集完成→租约移交归档进程→
有界复制→共享映射读锁释放→本地Flush与SQLite追溯记录→进程退出→
租约归还协调器→算法检测→结果事务确认→模拟PLC。协调循环不做图像或数据库IO。
沿用单工件及原工件截止时间，不增加隐式重试，不拓宽期限。

归档命令只接收两个描述符和64KiB以内配置，经stdin传递，先加入工位Job再发配置。
stdout/stderr合计8KiB；只有进程正常退出、回执身份一致且期限内才允许算法接纳。
停止/超时/崩溃必须隔离租约，确认子进程退出后才释放；不得提前复用槽位。
旧的纯内存及仅结果持久化API保持兼容。GUI持久模拟默认启用原始图像归档。

存储schema增量迁移保存run、inspection、camera通道、frame、布局、原始像素hash、
配方hash和对应有效配置快照。幂等重试必须全部一致；结果与图像通过run/inspection关联。
暂存文件先Flush再记元数据；中途失败可能留下可检查的暂存记录，不伪造完整工件成功。
图像本地归档与远端Available分别表达，不能把本地成功称为RustFS已上传。

验收：真实共享映射像素独立核对、两个相机身份、正常/NG/故障/停止/重启、
缺失归档程序、不可写/损坏数据库、旧配方或描述符冲突、资源归零；每步完整回归。
这一步不关闭T24/T27：掩码持久化、自动上传、远端保留清理/对账、
完整生产恢复和硬件验收继续保留。
