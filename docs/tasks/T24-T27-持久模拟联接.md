# T24/T27 持久模拟联接

2026-09-19。用户继续授权按现有文档开发，并要求模拟使用检查。
延续ADR-012/013：本批把已存在的模块接入模拟工位，不开启Production。

## 路径

原Volatile演示保持可选择。新增“持久模拟”使用同一模拟相机、算法与设备协调器，
另外创建独立SQLite输出宿主；结果及file意图同事务提交。
每次最多一个结果等待持久确认，等待时Ready撤销，不接纳下一个工件。
只收到匹配event的SQLite BusinessAcked后，才允许该结果发送给模拟PLC。
存储失败或确认不确定时禁止发送PLC结果并停止本轮；原质量保持不变。

检测结束、PLC确认及存储清算完成后，异步启动现有持久分发进程，
读取已提交意图，启动独立文件输出宿主，回写交付确认。
子进程配置通过有界stdin传入，避免在工位事件循环写配置文件。
清算进程纳入Windows Job，单次整体20秒截止；输出日志限制8KiB，溢出显式失败。
文件失败单独显示，不抹掉已持久结果，不伪造PLC交付失败。

用户中途停止：撤销接纳，取消未提交的物理动作，明确显示未确认的存储/输出；
已提交的意图保留供现有恢复工具核对。不得因为用户关闭窗口就补发物理动作。
每次UI持久模拟创建独立本地目录，显示目录及确认状态；测试使用临时目录。
目录创建属于启动准备，不在每帧/每工件循环执行。

## 验收

- 正常/NG/算法崩溃产生真实数据库记录及文件；内存模式旧测试全部保留。
- 数据库损坏或独占写锁时，没有未经持久确认的PLC结果，没有继续接纳。
- 输出写失败保留权威结果，清算报告失败；事件循环持续响应。
- 暂停/恢复、运行中停止、存储等待时停止、完成后再次启动。
- 实际GUI按钮路径与截图、SQLite/文件结果独立核对。
- 每步全量windows-all，最后额外一次完整回归。

不等于完成相机SDK、图像租约落盘、远端对象对账或真实PLC安全验收。

## 生命周期边界补充

存储启动失败时必须在工件触发前报告，不允许界面一直显示“等待”直到总超时。
中途停止的存储写入可能已经提交但尚未收到ACK，状态只能是Unknown；
即使内存已确认计数为0，也不能断言数据库没有记录或没有恢复意图。
文件清算过程被停止时不宣称文件未生成，显示Unknown并保留数据库证据。
UI模拟测试使用真实按钮信号，不用直接修改协调器状态制造通过。

文件完成报告必须核对持久意图的终态，不能只检查Pending为0：
Failed/Expired同样不在Pending集合内。清算工具按配置输出汇总已确认及未确认数量，
任何失败/到期记录不得得到“全部已交付”的成功报告；界面进一步核对确认数量不少于本轮已提交结果。
这项校验包括已有历史记录，因此旧失败会使整路报告不成功，需人工核对后再启动新的隔离运行目录。
