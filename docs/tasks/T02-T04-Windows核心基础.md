# T02～T04：Windows 核心基础实施批次

日期：2026-09-18。授权：用户要求暂不处理 Linux，按主计划在 Windows 上集中完成一批功能。

## 范围与顺序

1. T01 按 Windows 阶段退出，Linux 验证移至独立 V-LINUX 待验证项，发布前仍须验证，不伪称跨平台通过。
2. T02a：强类型身份、七类状态、统一错误与关联字段、版本和十进制 uint64 规则。
3. T02b：结果事件、配方和 manifest 的 Schema、正反例及严格读取器。JSON 只放编解码 target，不进入领域/runtime 公共接口。
4. T03：必需检查清单、全身份接纳、一次终结、Unknown 语义、局部证据、四种基础规则和有界幂等统计。
5. A05/T04：先记录组合预算设计，再实现本进程时钟、有界队列与原子多资源预算；远端票据及共享内存生命周期留给 T08/T12/T24。
6. 增加 CLI/Qt 演示入口；正常、缺陷、失败、超时、容量不足均可执行。不连接任何设备。

## 设计约束

- inspection 依赖 contracts，runtime 依赖 contracts；二者互不依赖。application 组装二者；JSON 适配单独链接 nlohmann/json 3.12.0。
- 领域对象由调用线程单写，不暗加互斥锁。每个检查只接受登记的 run/epoch/inspection/check/task/attempt；旧结果不能更改新任务。
- 必需检查全部成功才能形成 OK/NG；任何必需项失败/取消/超时则最终 Unknown，保留已收到的局部证据。缺项保持未完成，直到调用方明确超时。
- 本批规则：禁止类别、类别计数区间、分类允许集合、带单位测量区间。无目标对禁止规则为 OK，对计数按下限判断；缺少分类/测量或非法输入为错误，不能算 OK。
- 队列按条数和调用方提供的字节成本限流；不提供无限等待 API。关闭后拒绝新入队，已有数据可以排空。容量计数不等同于进程 RSS 硬上限。
- 本地组合预算一次锁内校验全部维度后才记账。预留可到期撤销；提交后的资源即使任务超时也不自动释放，必须由拥有者确认使用结束。移动式 RAII 票据只适用于本进程所有权，不代表跨进程图像租约。
- 配置协议 v1 拒绝未知字段/枚举、重复键、过大/过深输入以及不兼容版本。64 位数必须为规范十进制字符串，禁止数值 JSON 和前导零。
- 本批不创建真实生产控制或模拟“已就绪”。UI 和 CLI 明确标注合成数据演示。

## 验收

Windows core/gui 构建与测试；身份和异常数据负例；2^53 以上及 uint64 最大值往返；规则端点/缺项/失败零缺陷/重复与迟到报告；队列双上限、并发消费与关闭；预留回滚/提交/过期/幂等释放；CLI 各演示情景及配置校验；Schema 与示例一致。

完成状态依据实际验收记录填写，不以新增目录或测试数量替代验收。Linux、设备、共享内存、多进程崩溃隔离均不属于本批已实现能力。
