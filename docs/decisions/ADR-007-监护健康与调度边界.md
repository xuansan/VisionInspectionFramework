# ADR-007：Windows 监护、健康租约与调度边界

日期：2026-09-19。状态：采用。对应 A03/A07、T05 修补、T06/T07。

T09跟踪：[ADR-008](ADR-008-共享图像与插件宿主边界.md)与[VAL-010](../acceptance/VAL-20260919-010-共享图像与插件宿主验收.md)已补公共宿主的父PID+创建时间验证、启动期限和独立watchdog，覆盖本宿主Job绑定前的父退出；不扩大为任意外部进程都受保护。

## 决策

1. `vision_runtime` 提供纯 C++ Supervisor / ControlLease / TaskScheduler；`vision_runtime_qt` 管理 QProcess、本地 IPC 和 Windows 所有权。协调和质量规则不进入监护器。
2. Windows 以稳定工位 ID 的 SHA256 创建 `Global\VisionFrameworkStation-*` 命名 mutex。同名、无权限均拒绝启动，不删除别人的锁、不抢占。一个 StationGuard 对应一个 run_id，多个宿主共享它。调用方应统一工位配置；故意使用不同工位名不能保护同一物理设备。
3. 主控创建不继承句柄的 Job Object，设置 kill-on-close；工作进程启动后加入 Job，再允许 Configure。子进程在 Configure 前不能打开设备或执行生产命令。主控崩溃触发 Job 清理；独立的宿主健康租约也会停止孤立宿主。T09 公共宿主必须沿用此启动门禁。
4. mutex 获取成功不证明外部 PLC 会话已失效。新主控默认非生产；进入生产前必须完成旧宿主退出和设备会话核对。若不能证明旧控制者已撤销，拒绝 Ready，不按等待固定时间推断安全。T13/T23 实现 PLC fencing；无 fencing 的设备要求人工恢复。T06 不提供生产启动 API，不能绕过这些后续门槛。
5. 控制租约绑定 run_id、worker_id 对应的专有通道、epoch 和严格递增序号。使用现有 Heartbeat 的 progress_sequence 作为**发送方事件循环推进序号**；实际任务进度由 TaskProgress 独立报告。TTL 由双方配置，宿主根据本地单调时间计时。重复/旧身份不续期，到期不可原地复活；必须退出并由新 epoch 初始化。
6. 协调层显式调用 pulse_control，监护定时器不代替生产协调层续租。测试宿主 TTL 500ms；正式设备值必须通过配置契约协商，未协商时不能宣称支持设备健康租约。尚未首次收到有效租约的宿主不具有生产 Ready。
7. 默认监护阶段期限2秒、心跳1秒、任务进展2秒、停止宽限500ms；退避1、2、4秒，最多3次。为了避免慢性故障持续重启，本次显式启动期间采用**累计预算**，比原模拟“60秒内3次”的滚动窗口更保守，Ready 不清零；人工启动才重置。旧 epoch 退出事件不得修改新进程。退出未确认时不得释放远端资源或启动替代实例。
8. 请求预算耗尽后停止接纳，完成在途、排空发送，再正常停止/重启宿主形成新 epoch。成功轮换不消耗故障恢复预算，但失败轮换应按故障计数，不能造成无限重启。轮换不得续用旧任务身份。
9. IPC 最终回复从接收直到 pop() 之间仍由 pending 负责；已及时到达不再触发请求超时，交付前关闭按 Unknown 结算。应用回调收到后负责自己的任务结算；回调失败通过关闭事件撤销关联任务。关闭回调逐个异常隔离。
10. 调度器只维护执行状态，不计算质量；内部单调 task_id 不复用，有界保留任务和未消费终态。取消/超时先形成一次逻辑终态；运行资源直到匹配的停止证据或对应 worker/epoch 的 OS 退出才归还。迟到成功不能改变 TimedOut/Cancelled。不自动重试可能已有副作用的任务。
