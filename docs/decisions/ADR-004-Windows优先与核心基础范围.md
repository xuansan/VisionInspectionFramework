# ADR-004：Windows 优先与核心基础交付范围

日期：2026-09-18（UTC）。状态：采用。依据用户明确要求“先在 Windows 上跑通，不处理 Linux，一次推进较多开发任务”。

## 平台与阶段门槛

- T01～当前功能批次以 Windows x64 Release 验收；不再用 WSL2 故障阻止 Windows 功能开发。
- Linux 保留为 V-LINUX 待验证项，进入跨平台发布验收前补齐；原失败证据 VAL-005 保留。不删除 Linux preset，也不声明已经支持 Linux。
- T01 工具链、依赖决策、CMake、Windows 测试及 CI 定义满足本阶段退出条件。CI 配置存在不等于托管流水线已运行。
- 已批准的总体架构不变，不切换语言/UI、不引入低代码平台。本批实施 T02～T04，通过合成双检查项用例验证入口。

## 代码边界

`contracts`：强类型 ID、状态、错误、证据和结果值类型以及无外部依赖的基本不变量校验。

`inspection`：必需检查汇总、四类规则、配方模型、一次终结和有界去重计数。只依赖 contracts。

`runtime`：单调时钟端口/假时钟、按条数及字节成本限流的进程内队列、组合资源预算。只依赖 contracts，不含工件质量语义。

`serialization`：使用固定 nlohmann/json 3.12.0 实现协议边界。领域/runtime 不需要 JSON 类型。CLI/GUI 在入口装配序列化，不把它链接进 application。

`application`：小型合成演示协调器，调用 inspection/runtime。GUI 演示仅执行有固定小数据量的内存运算；未来真实推理、文件、网络和等待必须移至对应执行上下文，不得沿用 UI 按钮直接执行。

## 初版协议的准确范围

本批 v1 包含最终检测结果事件、配方、插件 manifest，以及参数模式的受限子集。持久化/图像/交付状态枚举已建立；对应异步状态事件、IPC 消息、共享内存描述及实际插件 ABI 分别在 T05/T08/T09/T14/T24 扩充，不能将当前结果 JSON 当成已经实现的全流程协议。

参数模式支持扁平 scalar（string/integer/number/boolean）、默认值合法性、数值范围、长度、枚举、单位、敏感标识、运行中可改性。暂不支持任意嵌套 JSON Schema、条件依赖或远程 `$ref`，未知关键词拒绝。整数参数限定 JSON 客户端可精确表达范围；64 位身份/时间字段使用字符串。

Schema 负责文档形状，C++ 读取器继续检查重复键、uint64 溢出、集合唯一性、检查项关联、范围顺序和最终质量语义。只通过外部 JSON Schema 检查不足以成为有效业务结果。

配方/模型哈希本批只检查格式；内容寻址、资产存在性及 hash 重算由 T15 实现。样例全零 hash 明确是合成占位，不能用于生产资产可信校验。manifest 样例 DLL 不存在，本批没有加载 DLL。

## 演示与生产能力

CLI/GUI 提供 OK、NG、算法失败、检查超时、容量不足五种情景。它们运行真实的领域、队列和预算代码，但输入为合成观察，不执行图像采集或 ONNX。每次调用独立统计，显示“本次计数”，不冒充产线累计数。

构建身份中的 `inspection_available=false` 仍指完整采集检测能力不可用，`demo_available=true` 表示核心演示入口可用。生产命令继续明确拒绝。
