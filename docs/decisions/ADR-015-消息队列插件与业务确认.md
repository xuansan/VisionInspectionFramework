# ADR-015：消息队列插件与业务确认

日期：2026-10-10。状态：已实现软件范围，Production 继续禁用。

## 决策

MQTT、Kafka、RabbitMQ、NATS JetStream 按协议分别放在
`plugins/message-queue/` 下，每项是独立 ResultOutput DLL，由独立
worker-host 执行。协议客户端不进入 runtime、inspection 或 UI。
迁移 MQTT 不改变插件 ID、参数及回执语义。

采用 librdkafka 2.8.0、rabbitmq-c 0.15.0、nats.c 3.9.1；
三个新增插件可选构建，默认关闭。当前 Windows x64 Release 静态客户端
只连接回环地址，TLS/SASL/远端集群不在本批范围。

复用既有 envelope、Dispatcher、宿主监护、AsyncOutput 和持久 agent。
不增加 SDK ABI 或新的通用消息总线。一个实例最多一项请求及一项未消费报告，
Busy 表示不能接收新请求。配置期限 100～800ms，任务硬停止仍由宿主承担。
协议库关闭、线程结束不等于任意系统调用都可强制取消。

## 确认语义

Kafka acks=all、RabbitMQ mandatory/publisher confirm、JetStream 发布确认
分别证明协议服务完成相应操作；它们不能证明 MES 等接收者完成业务。
只有精确匹配 event_id、output_instance_id、attempt 的 BusinessAcked
才回报成功。拒绝重复键、多余字段、畸形及超大业务回执。

Kafka 在发送前记录回执分区高水位，仅读取后续消息，不使用 consumer group；
每实例需要专属回执分区。RabbitMQ 每尝试创建私有临时回执队列，通过 reply_to
交给消费者。NATS 使用专属业务回执 subject，并核验发布确认的 stream/sequence。
后两者没有持久业务回执消费者，不承诺断线后找回已经丢失的回执。

失败或超时不意味着消息未投递。持久重放要求使用者显式声明
NonPhysicalIdempotent，接收端按 event_id 去重并确认当前 attempt。
不提供端到端 exactly-once，也不允许据此自动重放执行器动作。
NATS 不使用跨 attempt 的 broker 消息去重，避免重试无法再到达业务消费者。

## 验收与后续

正常、错误回执、离线、静默、取消、宿主并行健康输出及持久 agent
由契约/集成测试覆盖。受控故障对端与真实 broker 联调分别记录，
不能相互替代，详情见
[VAL-030](../acceptance/VAL-20261010-030-消息队列插件.md)。

客户端第三方 notices 随构建输出保留。测试服务器不编译进插件；
项目自身许可证仍待定。远端安全连接、长稳、集群故障、生产恢复、
实际 MES 与产线验收另行计划，不关闭相关生产父任务。
