# ADR-012：主控恢复与可靠分发意图（A04/A06）

2026-09-19，设计决策。关联审查§6/§8、主计划§11/§14/§17和T12/T14/T23/T24。
设计关闭不意味着生产持久化已实现。

## A06：重启恢复矩阵

新主控永远使用新run_id、新共享池和新设备会话；默认未就绪。旧Job退出确认前
不能授予新物理控制权；不能把历史Pending重新送到相机/PLC。

| 旧记录 | 重启后的解释 | 允许操作 |
|---|---|---|
| Pending/Running检测 | Interrupted，质量Unknown | 追加恢复事件；不重放触发 |
| 已完成结果 | 原终态不可修改 | 查询、非物理输出补发 |
| 图片Pending且有完整持久暂存 | 可校验hash后续传 | 新传输attempt，不重新检测 |
| 图片Pending但只有旧共享内存 | Failed/SourceLost | 保留检测结果，禁止虚构Available |
| PLC未确认/丢ACK/主控中断 | Unknown | 撤销Ready，人工或协议核对 |
| PLC业务ACK已持久确认 | 已交付 | 不重新剔除、不重放 |
| 非物理可靠输出未确认 | 持久intent驱动恢复 | 有期限、有限重试，同一幂等键 |

Demo纯内存运行明确不支持历史恢复，不声称恢复了丢失记录。没有完整持久存储、
真实设备控制权及联锁验证之前，Production入口始终拒绝。
T12验证暂停后在途仍归原工件、超时Unknown及新实例不复用旧run；
T13/T23验证旧设备会话/ACK拒绝；T24验证真实数据库恢复矩阵。

## A04：结果与分发意图的事务边界

ResultEnvelope不可变；交付状态另存，不得改质量。每个输出唯一键：
`(event_id, output_instance_id)`；请求幂等键在所有重试中保持不变，
attempt单调增加，只用于追踪，不作为新业务事件。

生产路径一个本地数据库事务必须同时：

1. 插入权威结果及事件（唯一run_id/inspection_id与event_id）。
2. 插入当时配置快照选定的所有必需输出intent（唯一event/output）。
3. 提交成功后才通知分发器。事务失败不得宣称结果Durable或可靠接纳。

分发器扫描已提交intent，不以一次内存通知作为唯一发送依据。每输出独立容量、
独立worker和重试预算；队列满不丢成成功。终态报告必须核对event、output、attempt、
宿主epoch；重复和迟到ACK不覆盖更新attempt。

| 故障点 | 恢复行为 |
|---|---|
| 事务提交前崩溃 | 事务回滚，无已提交结果/意图 |
| 提交后尚未发送 | 扫描intent并发送 |
| 已发送但ACK前崩溃 | 非物理接收端以幂等键去重；可能重复发送 |
| 接收端成功但本地ACK未持久 | 再次同键发送或查询；不声称exactly-once |
| ACK已持久 | 不再发送 |
| TTL已过 | Expired，不能发旧PLC动作 |

T14允许有界Demo outbox实现状态机及故障测试；若提供文件快照，明确原子可见性
不等于断电持久性，不替代T24数据库事务/磁盘满/fsync/损坏恢复验收。
重启补发只适用于明确配置的非物理输出；PLC永远走独立结果握手策略。
可靠输出持久性欠缺时，必须显示Demo/Volatile，禁止Production。
