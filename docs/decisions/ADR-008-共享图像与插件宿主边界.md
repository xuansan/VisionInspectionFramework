# ADR-008：共享图像与插件宿主边界

日期：2026-09-19。状态：采用。对应T08a/b/c、T09、ADR-007的I09跟踪。

## 图像通路

- contracts定义图像布局、owner、FrameLease和FrameDescriptor；serialization提供严格JSON编解码，64位字段和slot_id为十进制字符串。主控只操作BufferBroker账本，不复制图像。
- BufferBroker每池最多4096槽、每槽最多1GiB、像素预算最多4GiB，每槽最多64读者；Windows映射连元数据总量不超过4GiB。生产配置应远小于极限并按全机预算组合接纳。
- Windows页文件映射头320字节、槽头192字节、槽位步长64字节对齐。主控为每代写许可arm；写者按匹配generation/write_lease写入；写完在同一个mutex保护内发布头。读者用只读映射，取得mutex并核对完整描述后访问。初始化头也受槽0 mutex发布/获取保护。
- 池名按run/pool字符的hex编码生成，避免替换字符产生名称冲突。两个ID合计最多96字节以满足Windows对象名长度；新run或新pool必有新名。相同映射名已经存在时拒绝创建，不覆盖旧池。
- 读者调用visitor时持有槽锁；同槽多个读者被串行化，不伪称无锁多读并行。建议在visitor中做有限复制/同步计算，插件异步保存指针不受支持。Broker的租约仍是独立所有权账本，不以mutex替代租约。
- 超时使槽进入Retiring，直到最后一个精确匹配的释放或可信OS退出才回收。writer的Publish替换成全部读者许可，登记原子完成；不得拿写许可释放读者。
- WAIT_ABANDONED不解释为成功，检测方永久标记当前Mapping实例的槽为poisoned，通知协调方隔离并停止该池全部使用者。安全恢复方式是新pool名，不在旧映射内强行修复；在正式相机协调接入时必须保留这一路径。
- Mapping只能核对映射身份、布局和代次；活跃租约、owner是否为当前进程必须由控制端/消费者入口校验。它不是防恶意插件访问内存的安全边界。
- LatestPreview是有上限的副本，UI不能持有正式图像指针。首版支持Mono8、RGB8、BGR8，包括stride padding和offset。

## 插件及二进制边界

- plugin_sdk是无Qt接口target。固定MSVC v143动态CRT、x64、Release/Debug、API1；描述导出必须逐项匹配manifest。接口指针只在宿主内使用，跨DLL不转移STL分配所有权。
- 三个C导出负责描述、创建、销毁；创建端销毁对象。所有插件方法noexcept；违反规则或原生崩溃属于宿主故障，由进程监护处理。
- Library规范化入口DLL路径并限定包内，使用DLL目录和系统目录解析系统级依赖。manifest声明的插件依赖首版明确拒绝，不能假装已解析。该机制不是签名或供应链安全审查。
- 一宿主一个实例。Algorithm真实接通initialize/execute/request_stop/destroy；Camera、Communication、ObjectStorage、ResultOutput提供类型接口和所有权规则，业务宿主适配在T10/T13/T24/T14落地。
- execute输入/输出最多64KiB，结果由宿主再通过TaskFinished协议校验。不合法结果关闭通道，不变成OK。输出插件try_submit必须有限且非阻塞；remote ACK只通过poll_report报告。
- destroy失败不能证明回调清理完毕：保留模块映射直到宿主退出，公共宿主以非零码退出，禁止继续使用或热卸载。升级仍是停止并确认退出后替换。

## 公共宿主和启动竞态

- 主控把父PID及创建时间放入子进程环境。公共宿主最先打开并验证父进程句柄，再启动独立watchdog；随后才建立IPC，收到Configure后才能加载DLL（包括DllMain）。
- 正常ProcessHost在QProcess::started时加入Job，成功后才允许Configure。Job绑定前若主控死亡，宿主已启动时由watchdog发现；还没运行时通过父身份校验失败退出。
- 启动期限5秒；初始化成功后控制健康期限1秒。watchdog只观察父退出及已验证的控制租约到期，不能独立伪造续租。控制Heartbeat由真正主控协调循环发送、IPC线程校验严格递增序号后更新期限。
- 插件执行在专用线程上，控制IPC在事件线程；心跳不虚构算法进展。当前SDK没有细粒度算法进度回调，单次不可分割长推理应设置合适的progress期限，且仍受任务总期限裁决。后续SDK扩展需版本变更。
- 正常停止发出request_stop，等执行/销毁结束再退出；若插件不响应，外部Supervisor或watchdog有限终止。固定1秒租约及5秒启动期限为当前宿主配置契约，不宣称已适配所有工业设备。

## 验收范围与后续

T08验收图像池、租约和真实进程读写，不把独立实验叫做检测闭环。描述codec不自动把15种IPC消息扩展成新的采集工作流；T10负责实际采集发布消息和映射引用的协调入口。

T09验收SDK、兼容检查、Algorithm公共宿主及故障隔离；设备/存储/输出类型的实际实现仍按原任务编号推进。UI不增加生产控制。Linux、真实相机/GPU、长稳、OS内存硬限制和跨用户部署不在本批验收范围。
