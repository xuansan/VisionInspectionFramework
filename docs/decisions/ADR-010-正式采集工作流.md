# ADR-010：正式采集工作流

2026-09-19；采用，Windows模拟采集范围已验收，见[VAL-012](../acceptance/VAL-20260919-012-正式双相机采集链路.md)。用户批准T10b，完成后进入T11。

采用专用CaptureTask/CaptureFinished消息，不复用质量判定TaskFinished；共17类消息。头保留1.0，扩展能力capture-v1通过Hello required_capabilities门禁声明；旧实现不识别该能力必须拒绝握手。新版支持旧15类载荷，但不宣称与旧二进制混部兼容。

CaptureTask包含slot_count、slot_bytes、write_frame、budget_ns；完整correlation关联任务，write_frame所有者必须匹配会话。CaptureFinished包含execution_state、frame或null、error_code；成功帧必须逐字段等于请求写许可/图像布局/帧ID，无quality字段。

公共宿主专用执行线程串行加载/采集/关闭。每个请求打开Camera到指定池，trigger后有限周期poll；不伪造TaskProgress，进展期限由策略配置。取消标记在事件线程设置，并调用request_stop；执行线程也检查取消/预算，到终态前camera_close，关闭失败不报告已安全完成而关闭会话。只在完成关闭后发送终态，因而它证明本次写访问结束。正常池可继续使用；故障导致进程退出或映射损坏时新epoch/new pool，不自动重放旧任务。

应用采集协调器（Qt适配层）拥有ProcessHost、池和BufferBroker；每相机最多一个在途请求。超时/取消立即锁定本次结果且隔离写许可，停止宿主并等待OS退出；晚到成功不发布。正常完成先核对描述，再publish读租约。消费者显式release；慢消费者耗尽容量时拒绝新接纳。损坏/身份错误需要停止旧进程，旧消费者仍占有的池不得提前销毁/重用。

本批验收覆盖双相机、正常、缺帧超时、取消、断线/崩溃恢复、新epoch旧身份、发布背压和原全套测试。模拟插件会在每次open重置序号，因此正式采集模式为每任务独立会话；连续序列与重复/乱序注入需要插件保持采集序号直至initialize生命周期结束，此批同时调整，并保留本地回放测试。
