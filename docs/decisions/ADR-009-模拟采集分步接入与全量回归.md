# ADR-009：模拟采集分步接入与全量回归

日期：2026-09-19。状态：采用。关联T10、T09修补、CHG-009。

## 决策

沿既有Camera SDK和共享图像接口推进，不将设备逻辑放进runtime核心。T10拆为T10a采集源/真实DLL和T10b公共宿主/受认证采集工作流；父任务目标不变，两个步骤均完成才关闭T10。

T10a采用纯C++确定性图源、严格8位PGM/PPM解析、Windows共享映射写入。与直接引入全部OpenCV解码器相比，该范围易于定义容量和畸形输入行为；PNG/JPEG等格式待明确需要后扩展，不宣称已支持。与把模拟相机放入主控相比，DLL可以在独立工作进程运行，故障测试不必污染主控业务。仍使用T08正式FrameDescriptor，不建立第二套图像身份。

不改IPC1.0的15类消息，也不把图像描述JSON塞进只接受ID的input_ref/result_ref。T10b需要独立定义受认证写许可、帧完成通知、取消/超时及发布回执契约。当前测试进程用于证明DLL与共享图像接口，不是正式采集宿主。T11继续以完整T10为前置。

## 图源边界

最大4096×4096、单帧16MiB；单文件上限16MiB+4096字节头。固定图、显式列表序列回放、确定性合成图；列表最多256，按当前平面字符串参数的4096字节有效限额进一步受限。仅缓存当前帧与两个历史描述。文件解码瞬时存在原文件与像素副本两份，预算按约32MiB图像相关临时数据计算，不能误写成零拷贝。

delay/missing/duplicate/out_of_order/disconnect/crash为显式模拟参数，默认none；必须记录seed、fault_at、输入列表和配置。崩溃注入只能用于独立测试/模拟工作进程，不可在实际主控加载此类不受控代码。

## 修补及回归标准

Library关闭保存首次结果；第一次destroy失败后再次close仍报告失败，保留原DLL直到进程退出。

本批复核发现公共宿主lease测试的最终OS退出码可能被监督者Kill覆盖。改为受认证的真实公共宿主独立watchdog测试：无竞争Kill，保留退出42和过期间隔断言，另保留原ProcessHost全部回归。不延长生产健康租约。

按用户要求，后续每次正式测试都运行`node tools/build.cjs windows-all`：完整核心、GUI、IPC及现有Schema/CLI检查。失败继续收集其他独立套件结果，整体必须失败；不能以单个新用例通过关闭任务。环境准备探针属于依赖安装验收，不每次重装SDK或启动RustFS；真实设备、Linux、长稳仍是各自独立验收。

## 未解决项

T10b控制协议、采集与任务调度联合取消/恢复、双相机正式采集链路、T11算法入口、A04/A06持久恢复仍未完成。DLL同进程调用不是安全沙箱；受限路径也不能抵抗本机恶意资产替换。回放资产应使用受信任且运行期间不变的目录。
