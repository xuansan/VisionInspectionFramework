# ADR-013：存储与外部输出进程边界

2026-09-19，T22～T27批次实施决策。延续ADR-012，不替代其完整生产验收。

1. `vision_runtime`继续只管进程、期限、资源和监护，不引入SQL、HTTP、S3或质量判定。
   `vision_storage`和`vision_modbus`为独立非Qt库，并加入CMake依赖保护与反例测试。
2. 相机/PLC接入仍为设备插件；Modbus通信在Communication独立宿主中运行，
   TCP协议对端测试不能代替真实PLC看门狗、控制权和现场联锁验收。
3. SQLite、文件和HTTP均为ResultOutput插件，加载在各自worker-host。
   一个有界请求槽、一个有界报告槽、一个IO线程；IO线程只解决宿主内响应，
   最终卡死隔离依赖宿主进程，不依赖线程捕获异常。
4. HTTP在输出宿主中运行有限HTTP线程池；REST只读SQLite，SSE仅是有界实时窗口，
   不持有正式图像租约。HTTP接收确认不能被解释为远端订阅者业务确认。
5. 元数据与非物理交付意图同事务；独立`vision-durable-output-agent`
   从数据库领取带TTL/尝试号/会话令牌的意图，启动每路独立worker。
   它是有界清算工具，不在UI线程执行，也不是已经完成的生产常驻编排服务。
6. 对象上传工具使用本地持久暂存与持久目标登记；重启后的续传只需要数据库与暂存，
   不能重新触发相机或PLC。唯一目标约束阻止同一数据库内两张图覆盖相同对象位置。
   跨数据库/外部工具写同桶的冲突管理仍属于部署与完整对账。
7. 生产就绪证据属于application：必须匹配运行、配方、代次并保持新鲜。
   没有真实硬件验收、完整持久追溯与恢复编排时，Production继续拒绝。

新增本地依赖为已准备的SQLite、libcurl、cpp-httplib和RustFS集成测试程序；
Qt模块仍只有既有Core/Network/Gui/Widgets。框架自有许可证仍未选定，
本决策不把依赖的开源许可证转换为框架项目的发行许可。

剩余生产工作：图像租约到暂存服务的接入、完整追溯/恢复事件、
远端删除意图/保留/对账、持续分发/上传调度、真实PLC对账及UI实际依赖状态。
不得因为库/CLI已通过软件测试就关闭这些父任务。


2026-09-19后续落地：DurableSession通过独立SQLite宿主完成模拟结果提交，
持久确认后才交给模拟PLC；轮次结束异步调用独立清算进程生成文件。
Qt事件循环不执行SQL/S3，配置通过有界stdin发送；辅助进程加入Job并设总期限。
UI展示独立的持久/文件状态，依然拒绝Production；此联接不关闭剩余生产工作。
清算成功需核对持久终态汇总，Failed/Expired不能被Pending集合排除后伪装成功。


2026-09-20原图归档落地（VAL-026）：单工件双相机采集完成后，将正式读租约移交独立
vision-frame-archive进程；通过stdin发送有界描述符和配方快照，加入Job后才交付配置。
归档进程先复制像素并释放共享映射读锁，再执行Flush和SQL；正常退出且回执身份匹配后，

这是保守的顺序归档方案；高吞吐并发与长稳需要后续性能验收，不能直接声称满足现场节拍。
