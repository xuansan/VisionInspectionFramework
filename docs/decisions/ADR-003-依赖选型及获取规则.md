# ADR-003：T01 依赖选型及获取规则

日期：2026-09-18。状态：采用。关联 T01；延续已批准的工程基础收尾计划。

## 决定与适用范围

将已经下载并通过 Windows 探针验证的依赖作为首版开发基线，不因当前骨架只使用 Qt/doctest 而把其他依赖全部链接进主程序。

| 用途 | 选定基线 | 接入位置与限制 |
|---|---|---|
| JSON 编解码 | nlohmann/json 3.12.0 | 协议编解码实现；公共领域类型不暴露库类型 |
| 日志 | spdlog 1.17.0 | 日志适配；业务接口不依赖具体 logger |
| HTTP REST/SSE | cpp-httplib 0.56.0 | 独立 HTTP 输出宿主；容量、超时、慢客户端隔离另行实现 |
| S3 传输与签名 | libcurl 8.22.0 | 存储适配，Windows 基线 Schannel；不代表已有完整 S3 客户端 |
| 元数据 | SQLite 3.53.4 | 存储 worker 单写入者；事务/恢复按 T24 实现 |
| 对象服务 | RustFS 1.0.0 | 独立开发服务；生产部署和兼容性仍须 T24 验证 |
| 图像与推理 | OpenCV 4.12.0、ONNX Runtime CPU 1.30.0 | 相关 worker；GPU 不在本次基线内 |
| 桌面与测试 | Qt 6.8.3、doctest 2.5.3 | 延续 ADR-001 |

HTTP 选择现有独立 C++ 库，避免额外引入 Qt HTTP 模块；S3 使用已有 libcurl 签名/传输基础，业务层仍需实现请求构造、响应解析、对象键、失败分类、重试和对账。替代方案是引入完整云 SDK，优点是协议覆盖更多，代价是依赖及构建范围扩大；后续若实际接口覆盖不足，必须通过新决策调整，不能自行写一套不完整的兼容行为。

以上是开发选型，不是“所有库已经接入框架”或“全部生产验证完成”的声明。既有测试证据为 VAL-20260918-003。

## 获取与版本管理

当前采用 CMake 固定版本及显式离线 SDK，不引入包管理器。本机 SDK、安装包和参考仓库不进源码；允许入库的是 [制品锁定清单](../../dependencies/artifacts.lock.json)，保留版本、来源、SHA256、验证来源及适用范围。

清单从既有下载记录迁入。来源中的“本地记录哈希”不等于发布方签名。Qt 辅助图形包版本属于选定安装包组合，不把包内所有组件都解释成 Qt 6.8.3。

目前 CMake 只自动强制校验 doctest 单头文件；清单不是完整自动安装器。以后接入其他 target 时，必须增加对应制品验证和平台构建规则，禁止仅凭目录存在就接受任意版本。

Linux 核心无需 Qt 或其他业务 SDK。Linux 业务依赖源码/二进制、GPU、完整 Debug 和正式发布 SBOM 尚未覆盖。当前跨平台的最低要求是实际构建纯 C++ 核心，不能用 Windows 探针替代。

## 许可与升级

本记录不改变 ADR-001 与发布审查要求。自有 LICENSE 未决定；第三方许可文本、对应源码、传递依赖和发行材料仍须按实际发布包核对。

升级流程：提出原因与影响 → 更新清单和相应 CMake 锁定 → 验证受影响的 target/协议 → 追加验收与进度日志。禁止直接使用 latest 或静默回退到系统同名 DLL。
