# ADR-014：网络输出与对象存储插件闭环

日期：2026-10-09。状态：第一批实现；不解除 Production 限制。

## 决策

Webhook、MQTT 为 ResultOutput；S3 为 ObjectStorage。独立 worker-host
按插件 Kind 分派投递，复用现有有界 Dispatcher、进程监护及持久 agent，
不新增跨层网络调用，也不改变 SDK ABI。

ObjectStorage SDK 的通用操作入口本批只实现“已提交结果关联原图上传”。
原计划 put/head/get-access/delete 的通用 API 仍是目标，不宣称全部实现。
存储成功只在远端回读哈希核对后确认；沿用交付清算状态 BusinessAcked，
其含义仅是此存储操作完成，不能解释为远端业务消费。

MQTT 使用 Paho C 1.3.15 可选依赖；首批仅本机 broker，正式 broker、
TLS/认证和部署资源限制后续验收。Webhook 使用已有 libcurl。
不新增 Qt MQTT 或 Qt HTTP Server 依赖。

持久 agent 允许本地 file/http、受限 S3 存储；Webhook/MQTT 另须显式
NonPhysicalIdempotent 声明。声明来自使用方对接收端的确认，
不能证明远端幂等，更不能用来重放物理动作。仍是可重复投递，
不提供端到端恰好一次保证。

## 验收与范围

契约、故障、独立宿主、持久交付测试及全量回归见 VAL-029。
真实本地 RustFS 验证存储链；MQTT 测试使用受控协议对端，
不能代替正式 broker 互操作与压力验收。

GUI 默认仍用既有文件输出。未增加远端存储管理、掩码持久化、
通用 PLC 自动补发，亦未关闭 T22～T27 或 E01/E03 父项。
