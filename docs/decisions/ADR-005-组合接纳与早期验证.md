# ADR-005：组合接纳、可观测性与任务拆分

日期：2026-09-18（UTC）。状态：采用。关联 A05/A08/A09、T02/T04/T08/T12/T24。

## A05：接纳必须覆盖整个工件

应用在任何执行副作用前计算 AdmissionReservation 的完整需求：每相机槽位、算法任务位置、必需存储字节及作业位置。必需存图使用可证明的格式/编码最大成本；未知上限时拒绝配置，不使用平均压缩比作承诺。

本进程资源按稳定名称排序，在一次短锁内检查全部余额及票据数，全部满足后才扣减。任何维度不足则零扣减。预留有单调期限，零值、未知资源和期限加法溢出拒绝。票据移动传递，禁止复制所有权。

| 行为 | 本地 T04 | 后续跨宿主契约 |
|---|---|---|
| 预留 | Reserved，已扣容量，尚未执行 | 请求含 run/worker_epoch/reservation_id/工件关联/需求/期限；响应带原身份 |
| 提交 | Reserved→Committed；重复提交不重复扣减 | 全部必要预留到位后提交；未获全部提交确认前不开始软件触发 |
| 实际使用 | Committed 持续占用，所有者负责确认结束 | 对应任务或租约拥有者登记 InUse；不能由普通心跳替代结束确认 |
| 撤销 | 未提交可 release；幂等 | 依固定资源顺序请求、逆序补偿；远端确认释放前不把余额变成可用 |
| 过期 | 仅 Reserved 到期可释放 | 未提交票据到期失效；过期提交拒绝；本地/远端不共享 steady_clock 纪元 |
| 完成释放 | Released；重复 release 不重复加回 | 已使用资源必须确认完成、取消已停止或进程确实退出后再释放 |

运行线程卡死后不能靠 C++ 析构回收外部操作；T04 RAII 仅适用于所有权明确的本进程资源。它不等于共享内存 Lease。

### 远端失败和重启

T08/T12/T24 接入时必须实现有界异步状态机：

1. 各请求受单项与总接纳期限、待请求数量上限约束，不同步等待宿主。
2. 第二相机或必需存储拒绝时，撤销已获预留；未开始执行的部分提交也需回滚确认。
3. 提交 ACK 丢失视为结果未知，查询同一票据或终止相关会话后核对；不能假定“未收到等于未提交”。重复请求复用原票据 ID。
4. 票据绑定宿主 epoch；重启后旧票据不可提交。旧宿主仍可能访问的资源先隔离，在确认退出/释放前不复用。
5. `Committed/InUse` 超时仅使业务任务逻辑失效；不会自动回收可能仍被 SDK/GPU 使用的资源。
6. TTL 在接收方按本机单调时钟保守计时，回复剩余预算；主控用自己的总期限裁决，不传裸 time_point。

硬件触发采用事先批准的有限接纳窗口和预留额度。超出窗口或无匹配票据的实际触发，记录未检测工件、撤销就绪并通知现场策略；软件拒绝不能抹去已发生的物理事件。本批不实施现场握手。

### 验证落点

T04 本批验证组合失败零扣减、精确到期、重复提交/释放、占用后超时不回收、票据移动、总数上限及溢出。

T08/T12/T24 必须追加远端拒绝、ACK 丢失、旧 epoch、半提交、硬件窗口越界和进程退出后的容量核对。这些远端测试尚未执行。

## A08：每模块从首版带证据

- T02：统一关联字段和错误结构；不输出敏感参数值作为 JSON 解析错误片段。
- T04：队列 count/bytes/closed 与资源余额/有效票据快照，本批可查看并测试。
- T06：生命周期、epoch、退出原因、重启预算和控制租约可追踪。
- T08：槽位代次/读写租约/隔离余额可追踪。
- T14/T24：分发意图/outbox/上传状态和恢复次数可追踪。
- 每个任务同步交付自己的错误及故障测试，T28/T29 做整机整合，不首次补测。

软件预算与 OS 硬限制分开：本批限制的是排队成本和资源凭证，不保证进程 RSS/CPU/磁盘不会超额。Windows Job Object 等属于平台执行层后续实现。队列 payload 必须是无阻塞析构/移动的值类型，不允许封装同步设备调用。
