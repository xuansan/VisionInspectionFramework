# 检测与输出工作流v1

关联ADR-011/012、T11～T15，Windows Demo实施。IPC头仍为1.0，
双方Hello声明capture-v1、inspect-v1、device-v1、delivery-v1；
旧端拒绝未知必需能力，不支持静默混用旧worker。

## 图像与算法

CaptureTask/CaptureFinished保持采集契约，不带质量结论。
BufferBroker.transfer在原读者已停止访问的前提下原子更换租约ID/worker/epoch；
无释放后重新申请的空窗。InspectTask发送slot_count、slot_bytes、read_frame、budget_ns，
FrameDescriptor身份必须与消息认证身份一致，算法只读映射。
算法执行完毕销毁本次映射才发送TaskFinished；异常/超时先固定Unknown终态，
隔离图像池，确认对应epoch进程退出后清算。不能只凭超时回收槽位。

application/qt/Station单线程组合两条采集/算法链；一次原子预留两相机、两算法、
结果容量。总工件预算覆盖采集和执行；每阶段只用剩余时长。单工位一个在途、
一个未消费结果；队列满拒绝。Inspection负责业务汇总，ResultCounter在唯一位置计数。
最多4096件后需新会话，防止无限去重账本。

## 设备

见[模拟设备-v1](模拟设备-v1.md)。DeviceTask/DeviceFinished有完整correlation，
应答必须匹配session_id/command_sequence。单次快照原子更新结果和有效状态，
ACK匹配原工件，旧ACK不能完成当前交付。Ready数据过期撤销。
同一物理结果只提交一次，未知结果不盲重放。仅模拟协议，不是安全PLC。

## 输出

DeliveryTask：event（完整ResultEnvelope）、output_instance_id、attempt、budget_ns。
DeliveryFinished：event_id、output_instance_id、attempt、state、error_code。
Channel同时匹配完整correlation、event/output/attempt；重复或迟到报告不能覆盖状态。
非物理输出可承载旧run事件，消息correlation仍使用当前宿主run/epoch。

每输出一宿主、独立容量和期限；主控只发有界消息，不调用插件函数。
Accepted表示传输接纳，不等于持久化/远端接纳；只有明确回执才BusinessAcked。
断线/错ACK/挂死为Unknown，明确拒绝为Failed，过期为Expired。
结果质量不可被交付状态改变。

Demo账本最多128事件、最多8路输出、默认每路8条待交付；
单事件JSON最多32KiB，快照最多8MiB。活动期限用单调时钟，快照保存UTC期限；
恢复转换成最多10秒剩余预算，过期不发送。未知/已接纳可显式恢复为Pending，
保持幂等键、增加attempt；ACK已记录不重发。快照恢复严格验证重复键、深度、
输出名单、容量、事件契约，完整验证后才替换账本。

内存快照接口没有承诺自动持久化；F26真实事务/断电验证留在T24。
PLC不能经此非物理重发器补发历史动作。

## Demo入口

DemoRunner组合Station、DeviceSession和Dispatcher，实际应用事件循环pulse。
Qt/CLI共用Runner，UI不修改工件终态。启动配方冻结，所有相机/算法Configure
使用同一个有效快照hash。当前只支持启动时读取；T16再实现保存/切换/回退。
关闭/停止先撤销接纳，再停worker并清算。无真实SDK/GPU/RustFS依赖。
