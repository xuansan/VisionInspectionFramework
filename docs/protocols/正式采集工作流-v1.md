# 正式采集工作流 v1

日期：2026-09-19。依据ADR-010；Windows Release。T10b接通真实模拟Camera DLL、公共worker-host、受认证IPC和协调层Session。不是海康SDK或生产控制验收。

## 模块与所有权

`src/capture/qt/Session`是应用采集适配器，依赖ProcessHost、BufferBroker、Mapping和序列化；它不进入纯runtime/inspection。调用者在同一协调线程运行所有方法，并在实际控制循环调用pulse()续健康租约。不能用一个脱离协调逻辑的后台定时器制造健康。

每个Session独立工作进程、独立图像池；共享StationGuard属于同一主控。主控创建池和写许可，Camera只持有Writer访问，无法自行发布读租约。Session完成槽头核验后才向本地消费者返回正式读描述。

初版每相机一个在途任务，一个未取走完成记录，1～16个槽位。单帧最多16MiB，任务预算1～10,000,000,000ns，含接纳/序列化/发送时间；现有源尺寸及格式限额仍适用。消费者读租约30秒，到期不能继续读取，但不会强制复用，必须显式release。无自动丢弃业务帧。

Session只负责采集，不实现工件质量判定。它目前提供一个主控本地消费者，T11/T12还需接入算法进程消费者和工件级组合预算，不能把当前本地读租约当成跨宿主算法分发完成。

## 协议扩展

头版本仍是1.0，新增必需能力`capture-v1`。新版Channel双方Hello均声明该能力；旧二进制不支持时拒绝握手。未支持其他能力，不能在旧版本中静默忽略扩展。其他15类消息载荷不变，所有组件应成套升级。

| 类型 | payload | 请求语义 |
|---|---|---|
| CaptureTask | slot_count整数、slot_bytes字符串、write_frame对象、budget_ns字符串 | 完整correlation；等待CaptureFinished |
| CaptureFinished | execution_state、frame对象或null、error_code字符串或null | 原request_id与correlation；无quality字段 |

write_frame使用FrameDescriptor-v1。slot_count最多4096，slot_bytes最多1GiB，总像素容量最多4GiB，映射实现额外验证头部开销。帧布局在slot_bytes内，slot索引小于count；帧run/worker/epoch必须匹配消息身份。

成功状态Succeeded必须有完整frame、error_code=null；失败Failed/Cancelled/TimedOut必须frame=null、明确error_code。Channel、宿主和协调层都核验成功描述与原请求一致，不能将旧frame_id/lease/generation或其他布局回复当成本任务完成。未知字段、重复键、uint64溢出和伪造quality被拒绝。

TaskAccepted仍只表示接纳；Camera链路不生成虚假的TaskProgress。宿主采集线程中的poll不能替代主控健康心跳或延长任务预算。

## 正常路径

1. Session.start创建新池，启动ProcessHost；Job绑定、认证和Configure后，公共宿主加载Camera DLL并initialize。
2. 协调循环pulse续租，ready且有容量时capture(budget)分配写许可，arm槽位，发送CaptureTask。
3. 公共宿主在专用线程camera_open → trigger → poll。轮询Busy时间隔2ms，不在IPC事件线程执行磁盘/SDK操作。
4. 验证完成描述；camera_close成功才发送CaptureFinished。若关闭失败或无法确认访问结束，关闭连接，等OS退出清算。
5. Session核对期限/关联/描述，broker.publish为本地消费者建立读租约，读取槽头验证后产生Completion。
6. 调用者take_completion后，通过read(frame,visitor)访问只读像素；visitor不得保留span或在读取结束前release。随后显式release归还租约；取走Completion本身不释放图像。

单个任务结束会关闭Camera映射；同一DLL实例保留图源序号及最多两个历史描述，以支持跨任务序列图和故障注入。close/open不重置源序号；新进程重新initialize后序号从1开始。frame_id与task_id仍由主控递增分配，不能用源文件序号替代任务身份。

## 取消、超时和恢复

- 协调层取消/超时：先产生唯一失败终态、隔离写许可，发Cancel并停止宿主；active写所有权保留至精确epoch的OS退出。期间拒绝新接纳，晚到成功不能发布。
- 插件缺帧：宿主有本地预算，主控有独立权威期限，心跳不能掩盖任务不完成。忙轮询不自动延长预算。
- 插件失败：只有camera_close成功后的失败完成才能直接归还写许可；无法证明访问停止则等待进程退出。
- 崩溃/断线：有明确失败，不自动重放任务。调用者取走Completion、观察退出、释放所有旧读租约后，可显式start，产生新epoch和新池。
- 慢消费者：槽位用尽时capture返回false，不额外分配池或覆盖旧帧。旧消费者未释放时拒绝换池重启。
- 映射Abandoned：隔离并停止旧宿主，新start换池；不原地“修好”损坏槽位。
- 调用者必须持续pulse处理期限/退出；主控卡住时已有公共watchdog/Job负责进程保护，恢复协调后再结算结果。

每任务预算最多10秒；采集适配器配置11秒进展监护上限，外部任务预算通常更短。这个独立采集策略不改已有算法默认策略，也不表示10秒适用于真实产线。

## 使用和演示

```powershell
.\out\build\windows-ipc\apps\capture-demo\Release\vision-capture-demo.exe `
  .\out\build\windows-ipc\apps\worker-host\Release\vision-worker-host.exe `
  .\out\build\windows-ipc\plugins\sim-camera\Release\sim-camera.json
```

演示启动两台模拟相机，各采三帧，输出六条JSON（mode=Demo、state=Captured、production_result=false）、像素字节数与像素和，释放租约并自动退出。像素和用于演示读到了数据，不是密码学校验。集成测试另做逐字节比较。

Qt旧五情景界面尚未接入这条链路。后续T11接算法，T12再统一工件触发/关联与生产状态；当前不能用作真实产线程序。
