# 共享图像v1：开发接口和调用顺序

依据：ADR-008。Windows x64，小端固定宽度头；其他平台尚未实现。

## 调用顺序

1. 每相机新建PoolSpec与Mapping::create、BufferBroker，运行ID与池ID合计不超过96字符。名称只在create成功后交给宿主。
2. broker.acquire得到写许可；owner.arm采用零等待，Busy则归还未发出的写许可，不能阻塞控制循环。
3. 相机端Mapping::open(Writer)；使用许可构造FrameDescriptor；write检查布局、数据长度和代次并复制。返回Ok才允许Publish。
4. 主控核对完整身份，broker.publish一次性登记全部读者；用encode_frame传只读描述。失败时writer仍负责证明已停止访问并释放或被终止。
5. 消费者首先校验描述owner就是自身会话，协调器通过authorized确认租约，再调用Mapping::read；visitor结束后不再持有span，最后发release。
6. release必须由消息来源与FrameOwner共同验证；broker自身比较run/pool/owner/epoch/slot/generation/lease。重复释放返回false但不影响余额。
7. 任何Abandoned或不可验证内容都隔离槽位；等待所有旧使用者停止，使用新pool恢复。新主控不复用旧run或旧pool。

read最多等待1000ms，调用方应使用更短业务上限；write/arm零等待。read visitor自身不能无限阻塞，一旦违约由进程监护终止消费者，不能从主控强行解锁。

## 描述字段

`schema_version=1`；run_id/pool_id/worker_id/frame_id是强类型标识；worker_epoch、slot_id、slot_generation、lease_id、stride、offset、length为规范十进制字符串；width/height为正uint32；pixel_format仅Mono8/RGB8/BGR8。

长度为stride×height，stride至少width×通道数，offset+length不超过槽容量；所有乘加检查溢出。额外字段、重复JSON键、错误类型、未知版本/格式和零epoch/generation/lease被拒绝。

头结构与static_assert见`src/frame_transport/include/vision/frame_transport/mapping.hpp`。共享内存里没有STL、裸跨进程指针或C++对象虚表。

## 所有权

Mapping只负责像素访问和同步；BufferBroker负责活动租约，Supervisor提供可信OS退出事实。三个职责不能互相替代。软件期限不证明进程已经停止，PID数字相同也不证明是同一次进程。

LatestPreview复制有限字节且覆盖旧预览；正式检测、存储和算法消费者不得靠预览丢帧策略释放正式租约。
