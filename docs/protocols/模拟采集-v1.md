# 模拟采集v1：T10a实际接口

实现：`src/capture`、`plugins/sim-camera`、`plugin_runtime::Library::camera_*`。Windows x64 Release，SDK API1保持不变，Qt未进入采集源或插件。T10b已增加公共worker-host的Camera执行入口，必须经主控身份/认证/Configure及CaptureTask调用，详见[正式采集工作流](正式采集工作流-v1.md)。

## 文件和构建产物

构建会在`out/build/<preset>/plugins/sim-camera/Release/`生成DLL、`sim-camera.json`和许可证待定说明。此包用于开发，manifest为NOASSERTION，不代表已经选择开源许可证。

最小参数：

```json
{"source":"synthetic","width":8,"height":4,"channels":1,"seed":42,"fault":"none"}
```

固定图参数示意（root必须真实存在）：

```json
{"source":"fixed","root":"C:/assets","files_json":"[\"part.pgm\"]","width":8,"height":4,"channels":1}
```

序列使用`source:"sequence"`，files_json显式给出文件顺序；按列表循环，帧序号从1开始。固定图重复读同一文件。最大256项，整个files_json字符串经过现有平面参数校验，实际上还受4096字节限制；不是无限文件列表。文件变坏、丢失或长度改变时返回失败。

仅接受PGM P5/PPM P6、maximum=255、Mono8/RGB8、紧密排列、offset=0。头支持空白/注释及CRLF约定，raster长度必须精确；首个像素即使是空白字节也必须保留。格式后缀不替代内容检查。最大宽高4096，像素最多16MiB，头最多4096字节；不支持BGR文件、PNG/JPEG、16位PNM。

## 调用顺序

所有调用在同一工作线程，唯一并发入口为request_stop：

1. Library::load → initialize → camera_enumerate。
2. 主控创建池并提供固定设置，camera_open打开Writer映射：

```json
{"run_id":"run-1","pool_id":"pool-1","worker_id":"camera-1","worker_epoch":"1","slot_count":2,"slot_bytes":"32"}
```

3. 主控BufferBroker.acquire后Mapping.arm，再将正式FrameDescriptor JSON交给camera_trigger。描述的布局、run/pool/worker/epoch必须与源/会话一致，lease必须递增。
4. camera_poll返回Busy时保持原写许可；Ok时返回写入完成描述。调用方核对本次许可和帧身份，再调用broker.publish发读租约；Camera不会自行发布。
5. 消费者按既有只读映射/授权核验读取，完成后归还自身读租约。
6. 停止时request_stop；等poll结束、camera_close成功或实际进程退出后，协调方才能按规则结算资源。Library::close自动调用已打开Camera的close，再destroy，保存首次关闭结果。

trigger只保存一个待执行任务，第二个返回Busy；磁盘读取在poll所在插件线程运行，不能在主控/UI线程调用。输出buffer不足时Busy，已完成描述仍保留，下一次poll不重新写图。失败/Cancelled不携带成功描述。

## 故障注入

| fault | 在fault_at对应的本次插件实例触发序号发生的行为 |
|---|---|
| none | 正常，默认值 |
| delay | delay_ms到期前Busy，范围0～10000 |
| missing | 始终Busy，直到取消/关闭，期限由宿主决定 |
| duplicate | 返回上一帧描述，不写当前槽位；至少已有一帧 |
| out_of_order | 返回前两帧的旧描述；至少已有两帧 |
| disconnect | Failed，后续触发失败，close/open后重新建立会话 |
| crash | 当前进程退出86，不返回帧，等待主控按OS退出事实回收 |

fault_at是正uint64十进制字符串，默认`"1"`。旧帧注入无足够历史时Invalid；不会伪造一张有效新帧。历史最多两个描述，不持有历史图像租约。

duplicate/out_of_order故意违反“当前触发应返回当前帧”的业务约定，用于验证接收方防御。不能因为poll返回Ok就无条件发布；必须完整对比期望身份。取消标记在close/open后重置；open不能与旧poll并发。T10b起源序号和最多两个历史描述跨close/open保留，新插件实例重新开始；这是为了让每任务关闭映射后仍能连续回放。正式恢复已由Session使用新epoch/池，仍不能替代真实SDK重连验收。

## 验证与范围

源单元测试验证确定性、像素格式/长度、文件限制、相对路径越界及中文文件名。Camera集成验证加载器生命周期、错误许可、取消/缺帧、延迟、断线、旧描述、真实子进程共享写入/退出清算、固定图/序列回放和输出背压。

T10a进程实验使用受控测试驱动；T10b另接通正式采集控制协议和公共宿主。两者均不通过算法产生工件质量结论。状态以[进度台账](../../开发进度及计划.md)为准。
