# 核心契约 v1 与开发接口

版本 1，Windows 基础批次。当前实现范围与限制见 ADR-004/005。

## 编译层次

```text
CLI / Qt UI → application → inspection → contracts
                         → runtime → contracts
CLI / Qt UI → serialization → inspection / contracts
                            → nlohmann/json（私有依赖）
```

contracts、inspection、runtime、application 禁止直接链接 Qt/JSON/设备 SDK。CMake 白名单与反例测试保护已创建 target；不能以本检查代替完整 include 静态分析。

## API 与所有权

| API | 行为 |
|---|---|
| `Inspection(context, expected)` | 建立一次单线程拥有的检测实例，冻结必需/可选检查及具体任务身份 |
| `accept(CheckResult)` | 返回 Accepted/Finalized/Duplicate/Stale/UnknownCheck/Invalid/AlreadyFinalized；拒绝时不改状态 |
| `terminate(state, reason)` | 显式结束缺项，保留已有局部证据；已终结时无效 |
| `take_finalized()` | 同一对象仅交付一次最终结果，后续返回空 |
| `ResultCounter::add(result)` | 按 run+inspection 去重；达到容量返回 Full，不能丢掉旧身份继续误计数 |
| `BoundedQueue::try_push(value, bytes)` | Accepted/Full/TooLarge/Closed/InvalidCost；拒绝不移动输入 |
| `try_pop()` / `close()` | 不等待数据；关闭后可排空，禁止新增 |
| `ResourceBudget::try_reserve(amounts, ttl_ns)` | 原子检查所有本地资源维度；返回状态及移动式票据 |
| `Reservation::commit/release/state` | 提交幂等；未提交可过期；已提交必须确认实际工作结束后释放 |
| `decode_recipe/decode_manifest/decode_result` | 严格格式及语义校验，失败抛 ProtocolError |
| `validate_parameters(manifest, document, running)` | 初始完整配置检查必需项；运行中只接受标记可改的字段增量；不自动填充默认值 |

纯领域构造参数错误抛 invalid_argument；非法外部 JSON 在适配边界转换为 ProtocolError；正常背压使用状态返回，不靠抛异常。内存分配失败等非业务异常不冒充成功。

## 结果判定

仅必需检查决定最终质量。全部必需检查成功：有任一 NG 则 NG，否则 OK。必需项失败/取消/超时：质量 Unknown，失败原因优先级为 TimedOut > Failed > Cancelled。未收到的必需项保持 Running，由协调者在期限到达时显式终结。

可选检查可以保存证据，但不阻塞完成、不推翻必需检查质量；最后一个必需项使结果终结之后的任何报告均拒绝。第一次合法终态固定，矛盾重报也不覆盖。

缺陷列表保存检测证据，不以列表是否为空直接判定：计数规则可以允许出现某类目标；推理失败即使零目标也仍 Unknown。

规则边界：禁止类别的空目标为 OK；计数区间含两端；分类缺失为错误、不在允许集合为 NG；测量必须唯一、有限值和单位相同，端点包含性由配方指定，不自动换单位。

## JSON 与兼容性

- 根文档 UTF-8，最大 1 MiB、深度 32；重复键、未知字段、未知枚举拒绝。
- v1 只接受 `schema_version=1`，manifest 还要求 `sdk_api_version=1`。不静默兼容未知主版本。
- 序号、epoch、attempt、时间、耗时均使用规范十进制字符串。整数参数不是身份计数，其范围限定为 ±(2^53−1)。
- ID 为 1～128 个 ASCII 字母、数字、下划线、点、冒号或连字符；不同 ID 的 C++ 类型不可互换。
- 64 位上界、检查身份一致性、范围顺序等需 C++ 语义检查，Schema 不能独立表达所有约束。
- manifest 的 entry_library 与 license file 仅允许包内文件名，不接受路径；平台后缀与实例上限受检查。实际加载时的 ABI/导出版本校验留给 T09。
- Schema 文本字符长度按 JSON Schema 规则；运行端以 UTF-8 字节计数，可能更严格。参数字符串长度约束也按 UTF-8 字节实现，配置文档须沿用这个保守上限。
- 敏感标识是后续 UI/日志脱敏输入，不是凭据加密机制。本批参数解析错误不会拼接输入值。

## 开发命令

```powershell
node tools/build.cjs windows-core
node tools/build.cjs windows-gui
.\out\build\windows-core\apps\vision-cli\Release\vision-cli.exe --demo failure
.\out\build\windows-core\apps\vision-cli\Release\vision-cli.exe --validate-recipe examples/contracts/recipe-v1.json
python tools/generate_schemas.py --check
python tools/check_schemas.py --cli out/build/windows-core/apps/vision-cli/Release/vision-cli.exe
```

Schema 生成只用 Python 标准库；独立验证使用本机已有 jsonschema 4.18.4，不是 C++ 产品运行依赖。默认 CTest 不依赖 Python；主要语义正反例在 C++ 测试中执行。
