# 持久存储与输出使用说明

本批新增 `vision_storage`、SQLite输出、文件输出、HTTP输出及独立持久分发工具。
主控runtime仍不包含SQL、对象存储或HTTP业务。原Demo链路仍采用Volatile分发。
这些工具是可执行的软件基础，不代表T24/T27整体验收已经完成。

## 持久模拟工作站

工作站新增“持久模拟”复选框。开启后，每次运行创建独立`demo-runs/<唯一编号>/metadata`
和`files`目录（位于工作站可执行文件旁）。界面显示实际目录，退出后数据保留；
自动GUI测试使用临时目录，不污染人工使用的数据。

GUI默认启用原图本地归档。链路为：模拟相机 → 独立归档进程保存双相机原始像素和配方快照 → 算法结果 → 独立SQLite宿主事务提交 → 持久确认 →
模拟PLC结果握手 → 本轮结束后独立清算进程生成JSONL并回写交付状态。
等待提交时不接纳新工件；提交失败或确认不确定时不发送PLC结果。
显示/审计演示输出仍为Volatile，各自失败不代表持久结果失败。

存储状态、确认件数、文件状态分别显示。中途停止可能发生在“已提交但ACK未收到”
窗口，界面显示Unknown/PendingRecovery，不保证数据库没有写入，也不会补发物理动作。
再次启动创建新运行目录；需要恢复旧目录时使用显式恢复工具并核对记录。
存储不可用停止本轮，文件失败保留已提交结果与原检测质量。

目前GUI持久模拟保存原始图像本地暂存、布局/通道/工件关联、有效配方快照、结果元数据及非物理交付意图。
原始像素为.stage文件，按保存的布局解释；不是PNG/JPEG。远端自动上传、分割掩码、真实设备与完整生产恢复仍未验收。
图像Pending表示尚未远端Available，不能理解为本地一定尚未落盘；trace.local_integrity验证本地内容。勾选该选项不是进入Production。
程序API未指定archive_program时仍可只做结果持久化，不将其称为图像归档。

## SQLite与确认边界

SQLite WAL、synchronous FULL；结果、选定输出intent、交付期限在同一个事务提交。
重复event_id必须匹配原内容和路由；run_id/inspection_id唯一；冲突不能产生半条意图。
SQLite输出插件在独立宿主的IO线程完成事务后报告BusinessAcked：
这仅表示SQLite这个接收端已经提交，不表示file/HTTP等下游也已交付。

Store每个连接只允许创建线程操作；SQLite在进程间串行化写事务，忙等待50ms。
SQLite输出现在在专用IO线程内保留一个连接，首次提交时打开，线程退出时关闭；
不再每个工件重复开库/迁移/关闭。完整采集关联表和生产恢复服务仍未完成。
默认目录预算64MiB，暂存单图16MiB；数据库页数另有限制，预留128KiB辅助空间。
目录配额是软件接纳检查，并非操作系统级硬磁盘配额或完整断电保证。

Schema v2增加delivery_leases表，v3增加upload_jobs，v4增加archived_frames。
归档保存run/inspection/channel、正式帧描述符、配方hash和有效配置快照；图像ID由run/inspection/channel哈希生成。
结果提交拒绝已归档图像的配方不一致，归档同样拒绝与已有结果的配方冲突。
进程中途失败可能只有部分图像或孤立暂存；不存在跨文件和数据库的单一原子事务，不能假定两幅图同时成功。旧v1意图缺少可靠TTL，迁移后不得盲目补发。
新意图TTL60秒；领取租约3秒；最多3次尝试。同event/output幂等键保持不变。
领取事务更新尝试号和会话令牌；ACK必须匹配领取令牌、尝试号、未过期租约。
旧ACK、超期ACK不能覆盖新尝试，次数耗尽Failed，到期Expired。
所有交付状态独立于不可变检测质量。

## 命令入口

`vision-storage-tool.exe <commit|query|trace|upload|resume-uploads|recover> request.json`

- commit：root、event（标准ResultEnvelope）、outputs（非物理输出实例ID数组）。
- query：root、after（整数游标，默认0）、limit（1～200）。
- trace：root、event_id；返回权威result及关联images（布局、配方、hash、bytes、object_state、local_integrity）。本地缺失/损坏显示false，不改检测质量，不伪造远端不可用。
- upload：root、endpoint、bucket、key、image_id、file。
- resume-uploads：root；每次最多5个持久上传作业，使用已有暂存，无需原文件路径。
- recover：root；将旧Running记录标为Interrupted，不重新触发设备。

S3凭据从VISION_S3_ACCESS/VISION_S3_SECRET环境变量读取。
支持SigV4、HTTPS及本机loopback HTTP开发服务；关闭代理及重定向，连接500ms、总请求2秒。
上传先FlushFileBuffers暂存，再PUT并GET校验SHA256，随后标记Available。
上传失败保留Pending及暂存，不改变原检测结果；上传目标与尝试号存入数据库，
resume-uploads可以在进程重启后续传。最多3次尝试，耗尽或源文件丢失/损坏标为Failed。
同目录上传命令使用独占文件锁避免并发续传；锁随进程退出释放。
对象key由调用方配置，应使用工位/运行/图像身份生成；数据库拒绝同目标位置绑定不同图像。
常驻上传调度、远端对象清理及数据库/对象对账仍待完成。

`vision-durable-output-agent.exe config.json`从已经提交的intent领取非物理交付，
每输出一个独立worker-host，单次发送预算最多1秒；本次有界清算15秒后退出。
清算汇总包含配置输出的pending、acknowledged、unconfirmed，按持久记录计算；
退出码0要求所有相关意图BusinessAcked且无宿主故障，1表示故障或已有Failed/Expired，3表示仅有Pending。
不把“Pending=0”等同于全部交付成功；已有历史失败也会使本次整路汇总不成功。
支持--stdin读取至多64KiB配置，工作站持久模拟采用此入口，避免在协调循环写配置文件。
本工具已接入持久模拟GUI；生产主控的常驻调度仍待完成，不能当成Production路径。

配置示意（路径按本机构建位置填写）：

```json
{
  "root": "C:/data/vision/metadata",
  "host": "C:/vision/vision-worker-host.exe",
  "outputs": [
    {
      "id": "file",
      "manifest": "C:/vision/file-output.json",
      "parameters": {"root": "C:/data/vision/export", "format": "jsonl", "max_files": 64}
    }
  ]
}
```

领取器仅允许本批审计过的file/http插件ID，不接受Communication、PLC或其他物理控制插件。
同一存储根目录使用工位锁避免重复领取器并行控制；更换路径别名和现场权限需在部署验收处理。
HTTP BusinessAcked是进入实时窗口，不是远端订阅者可靠消费确认，重放工具不能把它升级为持久订阅。

## 文件输出

JSONL/CSV一条事件一个完整文件，以event_id的SHA256命名。
CSV包含核心字段及完整标准结果SHA256；字符串转义引号并防止常见公式开头。
同键同内容重试不重复生成，冲突报错；完整写入并Flush、发布成功后再删除最旧文件。
max_files为1～128，单文件64KiB，扫描条目上限256。
保留期外的事件再投递可能重新生成文件；这不是无限期全局去重账本。
文件、SQLite和HTTP插件都使用有界单请求IO线程，并由独立进程承担最终阻塞隔离。
