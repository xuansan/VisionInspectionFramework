# VAL-20261010-031：数据库输出插件

日期：2026-10-10。Windows x64 / MSVC v143 / Release。
范围：可选 MySQL、PostgreSQL ResultOutput；Production 继续禁用。

## 实现与边界

插件目录：`plugins/database/mysql-output`、`plugins/database/postgresql-output`。
数据库客户端限定于插件和专项验收程序，复用公共宿主、受限异步工具、
分发与持久 agent；没有新增 QtSql，没有在主控内执行数据库 IO。

每个事件事务写入结果、缺陷和已归档本地图像引用。按 event_id 判断重复，
校验内容摘要及检测身份，冲突拒绝；COMMIT 成功才报告 BusinessAcked。
连接失败不泄露客户端原始错误文本、账号或密码。
迁移由管理员显式执行，不在运行时自动建表或提升权限。

明文限定回环；verify-full 强制 TLS、校验证书链与主机名。
MySQL 使用 Connector/C 3.4.5 + OpenSSL，PostgreSQL 使用 libpq 17.4。
依赖构建、固定版本、补丁及许可见数据库目录 README 与开发环境说明。

每库五项无服务/故障对端测试：非法参数、拒绝连接、静默连接、取消、

真实 MySQL 8.4.4 / PostgreSQL 17.4 由脚本在临时目录与随机回环端口启动，
使用临时账号和专用数据库，结束后停止；不安装 Windows 服务、
不连接或覆盖用户数据库、不修改全局 PATH。

## 失败与修复记录

- 初次整体检查期间根 CMake 正被修改，Skill 指纹检查失败；
  原始证据保留在 `out/validation/full-2026-10-10T03-12-31-852Z/summary.json`。
- SChannel 后端没有兼容本批需要的异步 TLS 读写，改用 OpenSSL；
  Windows 上游构建同时引入两套加密实现导致重复符号，保存最小构建补丁。
- MySQL 客户端默认跳过本地地址主机名校验，错误主机名测试暴露此问题；
  保存强制校验补丁，最终三项 TLS 场景两库均通过。
- 测试辅助工具处理中文原生 SDK 路径失败，改为 ASCII 临时 SDK 缓存；
  缓存标记仅在 bin/share/lib 全部准备成功后写入。
