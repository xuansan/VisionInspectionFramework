# VAL-20261010-032：OpenCV 算法插件

日期：2026-10-10。Windows x64 / MSVC v143 / Release。
范围：OpenCV 4.12.0 可选 Algorithm；HALCON 未接入，Production 继续禁用。

## 实现

`plugins/algorithm/opencv` 提供可选插件、私有引擎、manifest、示例配置与说明。
复用 Algorithm ABI、独立 worker-host、标准检测 evidence、只读图像租约；
没有修改公共 SDK、结果协议或 runtime 算法职责。
根 CMake 只增加可选子目录；审查此差异后更新 Skill 指纹。
DLL 导入表确认算法插件依赖 OpenCV/Windows/CRT，没有 Qt DLL。
测试部署采用当前 SDK vc16 二进制与 MSVC v143 动态 CRT，实际加载成功。

四类模式：阈值/形态学、连通域统计/面积数量筛选、轴对齐像素尺寸、
固定尺度角度模板最佳位置。NG 是执行成功但不合格；
参数、图像、ROI、期限和资源超限为失败/Unknown。
图像限 4194304 像素、64 MiB、单边 4096；
筛选组件最多 50，测量最多 252，符合标准结果 256 条上限。
模板为受限二进制 PGM，最大 1024 每边，拒绝常量，限制估计运算量。
OpenCV 单线程；阶段间检查取消/期限，原生阻塞由公共宿主进程监督收敛。

## 专项验证

CTest `opencv.*` 共 9/9 通过，2.22 秒：

- 算法测试：精确组件面积、质心、宽高；NG 的尺寸框/多目标/无目标；
  ROI 原图坐标、面积筛选、padding、非零 offset、RGB/BGR；
  阈值边界与反向、开/闭操作、无效配置/布局、资源和证据超限；
  固定模板位置/分数/未找到/常量/超出 ROI、取消与截止时间。
- 实际 DLL：加载/初始化，真实共享内存 Writer/Reader 和非零 offset；
  像素尺寸结果、期限失败 Unknown、无效描述符、释放及停止。
- 工位：模拟双相机 -> 两个 OpenCV 宿主 -> 标准结果及序列化；
  OK、NG、异常 ROI、触发后立即停止、建立新工位的两次生命周期。
- 隔离：同一 StationGuard 下另一个测试 Algorithm 真实挂死/访问异常；
  监督进入 ManualIntervention，挂死原因 ProgressTimeout；
  健康 OpenCV 工位随后完成结果并清理租约。

隔离测试没有把故障注入开关放入正式 OpenCV 插件。
它验证同主控下不同插件进程隔离，不冒充实际 OpenCV 库自身崩溃实验。
cancel 测试验证触发后停止及资源清理，不承诺每次进入原生运算后才取消。
restart 建立新的 Station 生命周期，不测试已停止对象重复 start。

## 首轮问题及修复

- 专项程序未部署 OpenCV DLL：OpenCV imported target 原为目录局部，
  提升导入目标可见性并按实际配置复制 DLL；复测启动成功。
- 共享图像 fixture 误用 Owner mapping 写入：改为正式 Writer 句柄；
  未绕过映射权限或修改生产映射代码。
- 已停止 Station 原对象不支持重启：按已有生命周期建立新工位验证，
  不改变框架生命周期语义。
- 配置 64 个组件会超出标准测量上限：证据硬限 50，明确失败不截断；
  补资源反例。测试模板最小长度检查修正为支持合法小型 PGM。
