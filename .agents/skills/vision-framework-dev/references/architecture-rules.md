# 不应被业务开发破坏的边界

1. UI负责交互；application负责流程；inspection负责检测含义；runtime负责监督和资源机制。
   相机SDK、网络、磁盘、ONNX等具体工作不塞进运行内核。
2. 故障隔离依靠已有进程边界；同进程线程不能隔离访问违规。避免为了方便在UI直接加载业务插件。
3. 请求关联run/worker epoch/inspection/check/task/attempt，旧会话回执不得完成新任务。
4. 共享图像必须持有正式租约，描述符不是无限期有效地址。取消不等于子进程已停止访问。
5. 单请求、有界队列/日志/图像池和既定截止时间不能无说明扩容；满载须有明确拒绝和恢复路径。
6. 结果质量不可被存储或输出失败改写。Unknown不能伪装NG，未确认输出不能伪装没有发生。
7. 元数据与持久意图按已有事务边界；PLC动作不能因重启盲目补发，物理动作另有现场确认。
8. local stage、remote Available、文件完成、HTTP窗口接收、远端消费分别声明，不合并成“成功”。
9. Production准入保持诚实；模板不能移除禁用条件。适配器与SDK就绪不等于现场验证。
10. 标准接口/manifest/schema变更时成套更新并跑兼容反例；框架层依赖由cmake/Architecture.cmake检查。

出错时查看docs/acceptance中同模块的失败证据、tests中故障场景，再追踪源码。
没有证据时报告假设和下一验证动作，不把机器崩溃直接归因于某个进程超时。
